产品提案 · Codely 内置能力孵化

和 AI 的长对话，聊完长成一张图

ChatGraphic 是 Codely 的配套可视化工具： 自动解析本地会话——从第一句对话到方案、最终选择与对应任务， 一键生成可沉淀的导图，讨论不迷路、成果可复用。「边聊边长」的实时形态，在「事后出图」验证通过后引入。

位
定位：Codely 的 feature，以孵化方式推进

边界：不扩大数据暴露面

解析复用 Codely 既有模型链路与数据边界；渲染、存储、导出全程本地，离线可用。

v0.2 修订说明（落实 2026-09-14 评审意见，共 6 处）
  1. 验证路径重排：新增「阶段 0」——存量会话一次性出图 demo（约 3 周）先行验证需求；「实时生长」整体后移至 Phase 2。
  2. 数据边界澄清：修正 v0.1「数据不出机器」的绝对表述——解析复用 Codely 模型链路（同等数据边界），渲染 / 存储 / 导出全程本地。
  3. 定位明确 + 补风险：明确为 Codely 内置能力孵化项目（非独立产品）；风险表新增「需求不成立」「宿主内建替代」两项。
  4. Phase 1 范围收敛：收敛为「只读 + 导出」，编辑 / 标注移至 Phase 2，消除 v0.1「CLI 形态 vs 可编辑功能」的矛盾。
  5. 指标口径修正：成功指标全部改为行为可观测口径（出图 / 导出 / 引用 / 定性复述），并声明小样本仅作方向判断。
  6. 技术方案补强：新增「三问准入线」「增量解析上下文对策（滚动窗口 + 图状态摘要）」「每轮边际成本量级」三处关键说明。

Why ChatGraphic

为什么需要它

AI 编程工具解决了「写代码」，但没有解决「讨论的沉淀」——长对话里，最有价值的结论最容易丢。

  • ✕对话太长，找结论靠翻记录。一次会话动辄几十上百轮，「刚才说好的方案」回头要翻很久。
  • ✕方案讨论没有落点。A/B 方案的取舍埋在对话流里，事后说不清「当时为什么这么定」。
  • ✕任务状态靠脑子记。AI 记得上下文，人记不全——做完了什么、还剩什么，全凭翻聊天记录。
  • ✕有价值的讨论无法沉淀。方案与决策随会话结束而消失，进不了文档、周报和评审材料。
产品方案

会话，即导图

导图从第一句对话起笔：讨论过的方案自动成为分支，最终选定的方案高亮标记， 选定方案之下再展开对应任务；一键导出，成果可存、可查、可分享。

为什么是我们 · 3

数据同源闭环

导图与对话、文件变更同源，每个节点可回链到对话原文与代码改动——图不是「画」出来的，是「长」出来的。

Core Features

核心功能

围绕「接入 — 出图 — 微调 — 沉淀」四个环节，每个功能标注交付阶段（Phase 1 = 事后出图 MVP，Phase 2 = 实时与内置）。

会话智能解析 Phase 1

读取 Codely 的本地会话，从第一句对话开始识别方案、最终选择与对应任务。

一键出图 Phase 1

会话结束一条命令生成整图；模板化分类骨架，先保证可靠与可读。

实时生长 · 增量同步 Phase 2

Hook 每轮增量解析、秒级上图；只解析新增轮次，上百轮长会话也不卡顿。

可编辑可标注 Phase 2

AI 生成的节点支持手动调整、增删与备注；编辑过的节点加锁，AI 只建议、不覆盖。

多格式导出 Phase 1

PNG / SVG / Markdown / OPML，直接贴进周报、README 与评审材料。

本地优先 Phase 1

渲染、存储、导出全程本地；解析与 Codely 同数据边界，不额外扩大暴露面，离线可用，可私有化。

Inside the Engine

技术方案 · 怎么做到的

六个关键技术决策——数据边界与 Codely 对齐、准确率靠分级与准入线、成本讲边际量级、状态靠证据优先、增量难点前置亮明、编辑权归用户。

解析引擎：同链路、同边界

解析调用与 Codely 对话走同一条模型链路，继承其数据处理边界与合规承诺——不新建服务、不新增模型、不扩大暴露面；结果本地合入，渲染与存储不出机器。

准确率：置信分级 + 三问准入

高置信度直接上图，拿不准的进「待确认」；上图内容过三问准入线——是否对应可执行任务 / 可复用决策 / 可追溯变更，都不是则不上图，守住图的信噪比。

状态推断：证据优先、语义兜底

「已完成」优先由文件变更与命令执行等真实证据驱动（覆盖代码类任务）；调研、讨论类任务以语义判断并标注来源，不冒充证据。

数据与编辑权：版本快照、人优先

导图为本地 JSON 工程文件，每次变更生成轻量快照，为对话回退与多会话合并预埋地基；用户编辑过的节点自动加锁——图的最终解释权在人。

增量解析：滚动窗口 + 图状态摘要 Phase 2 难点

长会话去重是核心两难：全量上下文成本线性涨，截断则节点重复。对策：解析输入 = 滚动窗口对话 + 当前图状态摘要，去重以图状态对比为准；MVP 先在全量解析中积累评测样本。

成本：边际可控、明码实价

解析仅在轮次结束触发（MVP 为一次性触发），输入为该轮对话 + 图状态摘要；目标：每轮附加延迟 < 2s、解析 token < 该轮对话的 10%，可一键关闭，超线自动降频。

Invest & Goals

人力与成本

2 人 · 3 + 7 周，闸门式投入

验证计划

先种子试用，再加码

阶段 0 后邀 5~8 名内部开发者试用 2 周（行为埋点 + 访谈）；「事后出图有人要」是 Phase 1 排期的前置条件。

成功指标（行为口径 · 方向判断）

出图 · 导出 · 引用

① ≥60% 试用者 2 周内主动出图 ≥3 次；② ≥40% 至少导出一张图；③ 出现 ≥3 例导图贴进文档 / PR / 周报；④ 定性：不翻记录能复述「上次定了什么」。样本量小，指标仅作方向判断，不作统计结论。

Risks

风险与对策

按严重程度排列，每个风险都有明确的降级路径与止损线，不赌单点。

需求不成立：事后出图也没人要核心价值假设验证失败
对策：阶段 0 仅约 3 周、5~8 人试用即可得出结论，止损成本有界；若未过闸门即止损，沉淀的解析能力可反哺 Codely 会话摘要功能。
宿主内建替代Codely 自己做会话摘要 / 大纲
对策：定位本就是内置能力孵化，按 feature 路径推进；与引擎团队对齐分工——宿主做「摘要」，本项目做「结构化可视化与沉淀」，避免重复建设；最坏情况并入宿主迭代，投入转化为 Codely 功能。
解析准确率不达预期方案 / 任务识别错误或漏识别
对策：置信度分级 + 「待确认」分支兜底；阶段 0 / Phase 1 建立评测集，人工修正样本反哺优化；最坏退化为「半自动导图」，仍优于手工整理。
每轮边际成本与延迟超预期解析拖慢对话响应 / token 超线
对策：仅在轮次结束触发、提示词精简；目标附加延迟 < 2s、解析 token < 该轮对话 10%，超线自动降频，支持一键关闭（MVP 为一次性触发，无此风险）。
Codely Hook 能力受限事件粒度或稳定性不足
对策：该依赖已后移至 Phase 2，MVP 不受影响；届时降级为会话文件监听，实时性从「秒级」退为「轮次级」；与引擎团队共建 Hook 规范列入协作项。
独立安装摩擦大、长会话导图过大用户懒得装 / 上百轮对话节点爆炸
对策：Phase 2 并入 Codely 内置视图随宿主分发，导出 PNG 零成本分享；画布侧分支自动折叠 + 按任务聚合 + 增量布局，只解析新增轮次。
FAQ

预判问题

评审现场最可能被问到的五个问题。

Q1 · 解析错了怎么办？导图会误导人吗？

高置信度内容才直接上图，其余进入「待确认」虚线分支等用户确认；节点均可一键修正，人工修正会作为样本持续优化解析。

Q2 · 解析的模型成本有多大？

解析仅在轮次结束触发（MVP 为一次性触发），输入为该轮对话 + 图状态摘要；目标：附加延迟 < 2s、解析 token < 该轮对话的 10%，可一键关闭。v0.1「不新增成本」的表述已修正为「边际可控、明码实价」。

Q3 · 会不会打扰写代码、抢注意力？

MVP 是纯被动的按需出图——不弹窗、不常驻、想用才用；Phase 2 实时形态默认静默常驻、可随时关闭，定位是「后视镜」而非「副驾」——不抢方向盘。

Q4 · 和 XMind / ProcessOn、会话记录工具有什么区别？

导图工具只画图、不管对话；记录工具只存档、不生成结构。ChatGraphic 与对话同源、自动生成，节点可回链到原文与代码变更——这是它们都做不到的。宿主自身的会话摘要功能与本产品是「摘要 vs 结构化可视化」的分工关系，详见风险表。

Q5 · 代码与对话数据安全吗？

渲染、存储、导出全程本地；解析调用与 Codely 对话同一模型链路、同等数据边界——Codely 能处理的会话即为本产品可解析的会话，不额外扩大暴露面（v0.1「数据不出机器」已修正为此口径）。导出与分享支持脱敏（隐藏代码片段），企业空间版本提供权限与审计。

会话导图 · Codely 配套可视化工具

和 AI 对话的同时，看着导图实时生长

ChatGraphic 是 Codely 的配套可视化工具： 对话进行中即实时解析——从第一句对话到方案、最终选择与对应任务， 导图随讨论同步生长，聊完即得图。讨论不迷路，成果可沉淀。 实时以轮次级起步（每轮结束数秒内更新），秒级在 Phase 2 做实。

位
定位：Codely 的 feature，以孵化方式推进

终局是 Codely 内置视图——不做独立产品、不建独立网站、不与宿主争夺入口；按 feature 立项路径排期与评审。

路
路径：实时优先，Phase 1 只做「轮次级」

依托 Codely Hook 在轮次结束触发解析，MVP 全量重解析（单会话秒级）；增量解析与秒级在 Phase 2 做实。行为数据不过线，即降级为事后工具。

界
边界：不扩大数据暴露面

解析复用 Codely 既有模型链路与数据边界；渲染、存储、导出全程本地，离线可用。

v0.3 修订说明（相对 v0.2：验证策略改为「实时优先」）
  1. 验证假设修正：放弃 v0.2 以「事后出图」为代理验证的设计——事后验证对核心假设「聊的时候看不看图」证据力弱、易假阳性；改为直接把图放进对话中验证。
  2. 实时的低成本实现：实时通道依赖 Codely Hook（文件监听经评估不可行）；MVP 只要求「轮次结束」一种事件 + 全量重解析，增量解析、细粒度事件与增量布局是 Phase 2 的优化项。
  3. 实时分层承诺：Phase 1 = 轮次级实时（轮次结束数秒内更新），Phase 2 = 秒级（细粒度事件 + 增量解析）；不重复 v0.1 一上来就承诺秒级的过度承诺。
  4. 降级路径写死：若 Phase 1 行为数据显示「聊时无人看图、仅聊后看」→ 降级为事后工具，解析能力反哺 Codely 会话摘要，不浪费。
  5. 指标改为实时行为口径：以「对话进行中打开面板」等直接行为作为核心证据。
  6. v0.2 其余修正全部保留：数据边界口径、宿主内建风险、feature 定位、三问准入线、只读先行、指标可观测原则。

Why ChatGraphic

为什么需要它

AI 编程工具解决了「写代码」，但没有解决「讨论的沉淀」——长对话里，最有价值的结论最容易丢。

  • ✕对话太长，找结论靠翻记录。一次会话动辄几十上百轮，「刚才说好的方案」回头要翻很久。
  • ✕方案讨论没有落点。A/B 方案的取舍埋在对话流里，事后说不清「当时为什么这么定」。
  • ✕任务状态靠脑子记。AI 记得上下文，人记不全——做完了什么、还剩什么，全凭翻聊天记录。
  • ✕有价值的讨论无法沉淀。方案与决策随会话结束而消失，进不了文档、周报和评审材料。
产品方案

会话，即导图

导图从第一句对话起笔：讨论过的方案自动成为分支，最终选定的方案高亮标记， 选定方案之下再展开对应任务；对话继续，导图实时生长；一键导出，成果可存、可查、可分享。

内置分发

随 Codely 安装与更新触达每个用户，零推广成本；第三方工具永远隔着一道「安装」的墙。

为什么是我们 · 3

数据同源闭环

导图与对话、文件变更同源，每个节点可回链到对话原文与代码改动——图不是「画」出来的，是「长」出来的。

Core Features

核心功能

围绕「接入 — 实时生长 — 微调 — 沉淀」四个环节，每个功能标注交付阶段（Phase 1 = 轮次级实时 MVP，Phase 2 = 秒级与内置）。

会话智能解析 Phase 1

读取 Codely 的本地会话，从第一句对话开始识别方案、最终选择与对应任务。

实时生长 · 轮次级 Phase 1

运行 watch 后导图随对话实时生长：每轮结束数秒内更新，无需等会话结束，也无需手动触发。

秒级增量同步 Phase 2

细粒度 Hook 事件 + 增量解析，只解析新增轮次；上百轮长会话秒级上图，不卡顿。

可编辑可标注 Phase 2

AI 生成的节点支持手动调整、增删与备注；编辑过的节点加锁，AI 只建议、不覆盖。

多格式导出 Phase 1

PNG / SVG / Markdown / OPML，直接贴进周报、README 与评审材料。

本地优先 Phase 1

渲染、存储、导出全程本地；解析与 Codely 同数据边界，不额外扩大暴露面，离线可用，可私有化。

Inside the Engine

技术方案 · 怎么做到的

六个关键技术决策——数据边界与 Codely 对齐、准确率靠分级与准入线、成本讲边际量级、状态靠证据优先、增量难点前置亮明、编辑权归用户。

解析引擎：Hook 驱动、同链路同边界

注册 Codely「轮次结束」Hook 触发解析——最小依赖仅此一种事件与会话载荷，Hook 只投递、解析异步执行、不阻塞对话（MVP 全量重解析，单会话秒级完成；Phase 2 升级增量）；解析与 Codely 对话同一条模型链路，继承其数据边界，不新建服务、不扩大暴露面，结果本地合入。

准确率：置信分级 + 三问准入

高置信度直接上图，拿不准的进「待确认」；上图内容过三问准入线——是否对应可执行任务 / 可复用决策 / 可追溯变更，都不是则不上图，守住图的信噪比。

状态推断：证据优先、语义兜底

「已完成」优先由文件变更与命令执行等真实证据驱动（覆盖代码类任务）；调研、讨论类任务以语义判断并标注来源，不冒充证据。

数据与编辑权：版本快照、人优先

导图为本地 JSON 工程文件，每次变更生成轻量快照，为对话回退与多会话合并预埋地基；用户编辑过的节点自动加锁——图的最终解释权在人。

增量解析：滚动窗口 + 图状态摘要 Phase 2 难点

长会话去重是核心两难：全量上下文成本线性涨，截断则节点重复。对策：解析输入 = 滚动窗口对话 + 当前图状态摘要，去重以图状态对比为准；MVP 先在全量解析中积累评测样本。

成本：边际可控、明码实价

MVP 每轮全量重解析——单会话数据量小、秒级完成，成本有界；Phase 2 增量解析（滚动窗口 + 图状态摘要）进一步降本。目标：附加延迟 < 2s、解析 token < 该轮对话的 10%，可一键关闭，超线自动降频。

Risks

风险与对策

按严重程度排列，每个风险都有明确的降级路径与止损线，不赌单点。

核心假设不成立：聊的时候没人看图实时面板无人使用，仅聊后查看
对策：行为埋点直接度量「对话进行中打开面板」；止损线写死——数据不过线即降级为事后工具，解析与出图能力反哺 Codely 会话摘要，不浪费。
Hook 是 Phase 1 硬依赖事件缺失 / 载荷不足 / 稳定性不够
对策：把对 Hook 的要求降到最低——仅需「轮次结束」一种事件与会话载荷；开工首周与引擎团队确认可用性并列入协作项；若短期不可得，先评估最小替代通道验证解析与图价值，实时随 Hook 就绪补上。
宿主内建替代Codely 自己做会话摘要 / 大纲
对策：定位本就是内置能力孵化，按 feature 路径推进；与引擎团队对齐分工——宿主做「摘要」，本项目做「结构化可视化与沉淀」，避免重复建设；最坏情况并入宿主迭代，投入转化为 Codely 功能。
解析准确率不达预期方案 / 任务识别错误或漏识别
对策：置信度分级 + 「待确认」分支兜底；Phase 1 建立解析评测集，人工修正样本反哺优化；最坏退化为「半自动导图」，仍优于手工整理。
每轮边际成本与延迟超预期解析拖慢对话响应 / token 超线
对策：MVP 全量重解析仅在轮次结束触发、单会话秒级完成、不阻塞对话；目标附加延迟 < 2s、解析 token < 该轮对话 10%，超线自动降频，支持一键关闭。
独立安装摩擦大、长会话导图过大用户懒得装 / 上百轮对话节点爆炸
对策：Phase 2 并入 Codely 内置视图随宿主分发，导出 PNG 零成本分享；画布侧分支自动折叠 + 按任务聚合 + 增量布局，只解析新增轮次。
FAQ

预判问题

评审现场最可能被问到的五个问题。

Q1 · 解析错了怎么办？导图会误导人吗？

高置信度内容才直接上图，其余进入「待确认」虚线分支等用户确认；节点均可一键修正，人工修正会作为样本持续优化解析。

Q2 · 实时解析的模型成本有多大？

MVP 为每轮结束后的全量重解析——单会话数据量小、秒级完成、成本有界，且不阻塞对话；Phase 2 增量解析（滚动窗口 + 图状态摘要）进一步降本。目标：附加延迟 < 2s、解析 token < 该轮对话的 10%，可一键关闭。v0.1「不新增成本」的表述已修正为「边际可控、明码实价」。

Q3 · 会不会打扰写代码、抢注意力？

实时面板默认静默常驻、可随时关闭——定位是「后视镜」而非「副驾」，不弹窗、不抢方向盘。「聊的时候会不会看图」本身是 Phase 1 要用行为数据验证的核心假设，答案不靠争论、靠数据。

Q4 · 和 XMind / ProcessOn、会话记录工具有什么区别？

导图工具只画图、不管对话；记录工具只存档、不生成结构。ChatGraphic 与对话同源、自动生成，节点可回链到原文与代码变更——这是它们都做不到的。宿主自身的会话摘要功能与本产品是「摘要 vs 结构化可视化」的分工关系，详见风险表。

Q5 · 代码与对话数据安全吗？

渲染、存储、导出全程本地；解析调用与 Codely 对话同一模型链路、同等数据边界——Codely 能处理的会话即为本产品可解析的会话，不额外扩大暴露面（v0.1「数据不出机器」已修正为此口径）。导出与分享支持脱敏（隐藏代码片段），企业空间版本提供权限与审计。
